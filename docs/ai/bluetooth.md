# 蓝牙与智能设备（M1）

M1 = GAN 智能计时器打通闭环 + GAN 智能魔方连通探测（MAC 自动解析 + 手输兜底）。
不改构建方式：全部原生 ES Module，无新增运行时依赖。

## 范围与现状

- 分支：`蓝牙尝试`（已合入 M1，真机联调待做）。
- 已做：
  - Web Bluetooth 连接、按 GATT 服务识别设备、断线处理；
  - GAN 智能计时器：状态帧、成绩帧、历史成绩读取；
  - GAN 智能魔方 Gen2 / Gen3 / Gen4：MAC 派生密钥、AES 同步解密、
    硬件信息 / 电量 / 面片 / 转动事件（Gen3 / Gen4 含丢帧补齐）；
  - MAC 自动解析：广播包 → 设备名 → 缓存 → 手输，错误 MAC 自动清缓存；
  - 计时联动：连上计时器后手放上 → 就绪，手离开 → 开始，停止帧 → 停表。
- 未做（M2）：
  - 已复原自动停表、成绩附带动作序列与回放；
  - 奇艺 / 魔域 / GoCube / Giiker（含按品牌名称规则生成 MAC 候选）；
  - 陀螺仪数据的界面使用。

## 协议要点

### GAN 智能计时器（最简单，M1 闭环用）

| 项 | 值 |
| --- | --- |
| 服务 | `0000fff0-0000-1000-8000-00805f9b34fb` |
| 状态（通知） | `0000fff5-...` |
| 成绩（读一次） | `0000fff2-...`，16 字节 = 当前 + 最近三次，每条 4 字节 |
| 帧 | `0xFE` 开头，末 2 字节 CRC-16/CCITT-FALSE（小端） |
| CRC 覆盖 | `[2, len-2)` |
| 状态字节 | byte3 只按索引表 `[0,1,2,3,4,9,6,7]` 取值：0 断开 / 1 就绪 / 2 手离开 / 3 计时中 / 4 停止 / 5 设备复位 / 6 手放上 / 7 已完成；越界按断开 |
| 成绩 | STOPPED 时 byte4 分、byte5 秒、byte6-7 毫秒（小端） |

byte3 是设备的状态索引，不是常量序号：常量 `IDLE = 5` 不会由这张表产生，
原始 5 对应 `GAN_RESET = 9`。直接把 byte3 当常量序号读，会把「设备复位」
误判成「空闲」，进而错误清空计时界面。

只订阅、不写，不需要 MAC 或密钥。

### GAN 智能魔方（Gen2 / Gen3 / Gen4）

| 代际 | 服务 | 写 | 读 / 通知 |
| --- | --- | --- | --- |
| Gen2 | `6e400001-b5a3-f393-e0a9-e50e24dc4179` | `28be4a4a-...` | `28be4cb6-...` |
| Gen3 | `8653000a-43e6-47b7-9cb0-5fc21d4ae340` | `8653000c-...` | `8653000b-...` |
| Gen4 | `00000010-0000-fff7-fff6-fff5fff4fff0` | `0000fff5-...` | `0000fff6-...` |

- 加密：AES-128-CBC。key / iv 用固定基底，前 6 字节与「倒序 MAC」相加后
  对 255 取模；每条消息只处理首块和末块 16 字节。
- 命令长度：Gen2 / Gen4 为 20 字节，Gen3 为 16 字节；命令也要加密。
- 事件类型（解密后）：
  - Gen2：`0x02` 转动、`0x04` 面片、`0x05` 硬件、`0x09` 电量、`0x01` 陀螺；
  - Gen3：`0x55` 魔数 + `0x01` 转动、`0x06` 历史、`0x02` 面片、`0x07` 硬件、`0x10` 电量；
  - Gen4：`0x01` 转动、`0xD1` 历史、`0xED` 面片、`0xFA`-`0xFE` 硬件、`0xEC` 陀螺、`0xEF` 电量。
- 转动必须先收到一次面片事件（串号闸门），否则丢弃；串号是 8 位环形，
  Gen3 / Gen4 丢帧时请求历史窗口补齐，请求窗口按奇数串号对齐。

密钥基底是社区逆向得到的互操作性常量，集中在 `gan.js`，来源说明见
`THIRD_PARTY_NOTICES.md`。

## MAC 策略

Web Bluetooth 不提供适配器 MAC，而 GAN Gen2-4 的密钥需要 MAC。

现在按四级降级解析（`mac.js` 的 `resolveMac`，顺序固定）：

| 级别 | 来源 | 条件 / 说明 |
| --- | --- | --- |
| 1 | 用户手输 | 明确意图优先，可用于纠正错误的缓存 |
| 2 | 广播包厂商数据 | `watchAdvertisements()` + `optionalManufacturerData`（CIC `0x??01` 全段）；末 9 字节里取最后 6 字节倒序；必须在 `gatt.connect()` 之前开始监听 |
| 3 | 设备名 | 只接受名字里完整的 12 位十六进制，不拿 3-4 位后缀猜 OUI |
| 4 | 本地缓存 | `localStorage["td_hw_mac_v1"]` 按设备名保存；首次解码成功后才写入 |

- 没有可用的地址时直接报错，提示手输（魔方卡片 / 官方 App），不会拿别的设备的
  缓存去试。
- 解析结果会在弹窗里显示「MAC 来源」，手输框自动带出实际使用的地址。
- 广播监听在连接前启动：已有缓存等 1.5s，没有缓存等 4s；计时器连接会在识别
  设备类型后立即停止监听。
- MAC 错误不会抛异常，只会静默解出垃圾：连续 40 帧解不出事件时提示；
  如果地址来自缓存或设备名，同时清掉这台设备的缓存，让用户重输。
- 广播数据并非所有平台都会给（尤其 Windows 桌面 Chrome 可能被实验开关限制），
  失败时静默回落到下一级，不阻塞连接。

## 计时联动

连上 GAN 计时器即接管，不需要额外开关：

| 设备状态 | 计时器动作 |
| --- | --- |
| `HANDS_ON` | 进入 ready（等同长按 0.8s 完成） |
| `HANDS_OFF` | 撤销 ready |
| `RUNNING` | 开始计时 |
| `STOPPED` | 停表并按现有规则记录 |
| `GAN_RESET` | 撤销 ready（复位是设备动作，不清计时显示） |
| `DISCONNECT` | 撤销 ready |
| `IDLE` | 复位显示（该状态不会由计时器索引表产生） |

- 成绩时间仍取本机 `performance.now()`，不改计时规则；设备上报时间只用于
  弹窗显示，后续是否改用设备时间需要单独确认。
- 断开时只撤销 ready，不会中断正在进行的计时。
- 观察模式与外部计时器同时开启时，外部事件优先（M1 未做冲突提示）。

## 限制

- 仅 Chrome / Edge（桌面、Android）；iOS Safari 没有 Web Bluetooth。
- 必须 HTTPS 或 localhost，且由用户手势触发；刷新后需重新授权。
- 未做真机联调：帧格式来自公开实现（gan-web-bluetooth，MIT）与本机源码核对，
  MAC / 固件差异仍需设备验证。
- 弹窗「原始数据」保留最近 40 行收发十六进制，便于真机核对。
- 请求失败会显示用户可读的错误并附带原始异常（名称：信息）；只有用户真的取消
  选择框（耗时超过 300ms）才提示「已取消选择设备」，选择器打不开、适配器缺失
  一律按错误处理，不再误报为取消。

## 验证

```powershell
node --test tests/hardware-*.test.mjs
node --test tests/*.test.mjs
npm run lint
powershell -ExecutionPolicy Bypass -File tools/serve.ps1 -Port 8903
```

浏览器侧（无需真机）：

1. 打开蓝牙弹窗，按钮 / MAC 输入 / 原始数据布局正常。
2. 非法 MAC 提示格式错误；保存后刷新仍能带出；清除后缓存删除。
3. 取消设备选择时状态回到「已取消选择设备」；选择器打不开、系统无适配器时
   显示带原始异常的错误提示，控制台无报错。
4. 关闭弹窗后长按 / 空格计时照旧（ready → go → 计时 → 停表）。

真机侧（需要设备）：

1. 连接 GAN 计时器，手放上应进入 ready，手离开开始，拍停后成绩落库。
2. 连接 GAN 魔方并输入正确 MAC：显示型号 / 固件 / 电量，转动计数增加。
3. 不填 MAC 直接连接：支持广播的浏览器应显示「MAC 来源：广播包」并正常解码。
4. 故意输错 MAC：约 40 帧后提示；若用的是缓存 / 设备名地址，会同时清缓存。

## M2 计划

1. 面片事件 → 已复原判定，自动停表。
2. 成绩记录可选 `moves` 字段（不改既有结构，缺省兼容旧数据）。
3. 奇艺 / 魔域驱动 + 品牌名称规则生成 MAC 候选 + 抓包 fixture 回放测试。
4. GAN 计时器历史成绩列表接入弹窗。
