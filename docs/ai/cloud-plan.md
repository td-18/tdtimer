# 云端能力规划（会员 + 服务端求解）

> 状态：**暂缓（条件触发）**。2026-11-24 记录，当前不实施。
> 现行方向：求解能力保留在客户端，前端保持纯静态；本文作为"将来商业化"
> 的分支保留，只有在明确启动收费时才重新评估。
> 届时每完成一个阶段，同步更新本文与 `architecture.md`。

## 目标

- 面向国内用户的会员制变现，以月付为主。
- 新增的收费求解入口只在服务端（现有本地打乱引擎不变），避免"登录后才能用"
  只是障眼法。
- 为后续云同步、训练数据留下接口，但不把它们和求解绑死。

## 非目标（本阶段不做）

- 相机识别任意状态。
- 20 步以内的最优解（成本与收益不匹配，见 `decisions.md`）。
- 排行榜、社交、对战。
- 海外市场与多语言。

## 前提

### 主体与合规

- 个人主体不能直接做经营性互联网信息服务；本方案先用**第三方平台
  代收 + 激活码**，本站只做兑换和权益校验。
- 正式上线前补齐：用户协议、隐私政策、未成年人条款、注销与数据导出、
  退款规则、自动续费提示。
- 不满 14 周岁的用户需要监护人同意；不做面向未成年人的付费引导。
- 只存账号必需的最小信息；用户未开启同步时，不上传成绩明细。

### 许可

- 本项目是 GPL-3.0-only。收费本身不违反 GPL，前端继续公开源码。
- 服务端代码不对外分发时，GPL 不强制公开（这点与 AGPL 不同）；不要把
  AGPL 代码混进来，否则整条服务链路都要开源。
- **商业化前必须补齐 CubeRoot / 魔方根公式数据的书面商用授权**；
  目前只有口头公开许可。4x4 求解器来自 csTimer（GPLv3），搬运时注意来源。

## 架构

```text
Pages（静态前端，计时 / 打乱 / 公式库 / 本地成绩匿名可用）
   │ HTTPS
   ▼
Worker API
   ├─ D1   码、用户、权益、每日用量
   ├─ KV   magic link、限流计数、token 吊销
   ├─ R2   预编译求解表（约 10 MB 二进制）
   └─ 邮件服务 + Turnstile
```

- 前端继续无构建；`worker/` 独立部署，不参与前端打包。
- 求解请求必须经过会话 / 权益校验和配额扣减，结果在服务端复核。
- 免费层也走同一个 API，但配额更小，用匿名设备 id + IP 限流，不要求登录。

## 求解服务

- 复用 `src/scramble/wca/puzzles/333/` 的块模型、表和二阶段搜索，
  Worker 只做协议、配额与校验，不复制算法。
- 表在浏览器工具页生成一次，导出二进制后上传 R2；运行时直接加载，
  避免每个 isolate 冷启动重建（约 1 s CPU）。
- 每次求解：解析打乱 → `solveCube` → `verifySolution` → 扣配额 → 返回。
- `quality` 映射：`fast`（400 ms / 23 步）、`balanced`（1200 ms / 21 步）、
  `short`（3000 ms / 20 步）。不承诺最优。

### 已知限制：求解能力已经公开

`src/scramble/wca/puzzles/333/` 是完整的二阶段求解器，随站点下发，且以
GPL-3.0 公开。懂行的人可以直接在浏览器里调用它解任意状态。服务端化只能挡住
普通用户和批量抓取，挡不住开发者。

因此"防止白嫖"的定位是**降低滥用**，不是绝对保护；真正的付费价值应放在
配额、云同步、训练数据和体验上。

## 会员与配额

| 能力 | 免费 | 会员 |
| --- | --- | --- |
| 计时、打乱、公式库、本地成绩 | 可用 | 可用 |
| 逆序解（打乱反过来） | 可用 | 可用 |
| 求解 | 3 次/天/设备 | 20 次/天/账号 |
| 短解 `quality=short` | 不可用 | 可用 |
| 云同步 | 不可用 | 阶段 3 再定 |
| 导出 | 不可用 | 可用 |

原则：免费层必须自成完整计时器，付费买的是"更好"而不是"能用"。

## API 草案

| 方法 | 路径 | 说明 | 鉴权 |
| --- | --- | --- | --- |
| POST | `/redeem` | 兑换码换权益 token | 无，Turnstile + 限流 |
| POST | `/solve` | 求解一段打乱 | token 或匿名设备 |
| GET | `/me` | 权益、配额、设备 | token |
| POST | `/auth/magic-link` | 发登录链接（阶段 3） | 无 |
| POST | `/auth/logout` | 退出并吊销会话 | token |

```json
// POST /solve
{ "scramble": "R U R' U'", "quality": "balanced", "deviceId": "..." }

// 200
{ "moves": ["R", "U'"], "text": "R U'", "length": 2,
  "durationMs": 812, "verified": true,
  "quota": { "used": 3, "limit": 20, "resetAt": "2026-11-25T00:00:00Z" } }
```

错误码：`UNAUTHORIZED`、`QUOTA_EXCEEDED`、`INVALID_CODE`、`CODE_USED`、
`INVALID_SCRAMBLE`、`TIMEOUT`、`INTERNAL`。

## 数据表（D1）

```sql
codes(id, code_hash, plan, months, batch, created_at, used_by, used_at, revoked)
users(id, email_hash, created_at, status, age_declared)
entitlements(user_id, plan, starts_at, expires_at, source)
devices(id, user_id, first_seen, last_seen)
usage_daily(user_id, day, solve_count, last_solve_at)
```

- 激活码只存哈希，一次性，可吊销，支持批次。
- 匿名配额按设备 id + IP 哈希计数，不建用户记录。
- 不存成绩明细；同步是独立功能，单独建表。

## 分阶段

| 阶段 | 内容 | 完成标准 |
| --- | --- | --- |
| 0 | 定平台、定价、条款草稿 | 文档定稿，确认没有资质硬伤 |
| 1 | 激活码 + 权益 + `/solve` + 免费配额 | 兑换 → 求解 → 配额边界全部跑通 |
| 2 | 平台对接、续期、退款、到期提醒 | 一笔真实订单能自动开通 |
| 3 | 账号（magic link）、注销、导出 | 账号全生命周期可走通 |
| 4 | 运营看板、反滥用 | 只做聚合指标，不上个人画像 |

阶段 1 就能验证"有没有人付钱"，不要先做阶段 3。

## 风险

1. **资质与备案**：个人主体做经营性服务是灰色地带，靠平台代收规避，但不是零风险。
2. **未成年人**：充值退款、家长投诉是真实成本，退款政策要写清楚。
3. **国内访问速度**：Cloudflare 免费版在国内不稳定，必要时换香港节点。
4. **续费率**：计时器付费意愿低，求解器不稀缺；留住人靠云同步和训练数据。
5. **数据出境**：数据放 Cloudflare 属跨境，规模上来后要评估或迁回国内。
6. **平台依赖**：代收平台有抽成、结算周期和封号风险。

## 验收方式

- 单测：已知状态的求解结果通过 `verifySolution` 复核、配额边界、码一次性、
  非法打乱拒绝。
- 浏览器冒烟：兑换 → 求解 → 到期 → 配额用尽，控制台无报错。
- 压测：目标 QPS 下的 p95 延迟；表加载对冷启动的影响。
- 合规：隐私政策、注销、数据导出流程走查。
