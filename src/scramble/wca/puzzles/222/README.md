# 2x2 本地求解器（M1）

## 文件

| 文件 | 内容 |
|---|---|
| `cubie.js` | 8 角块模型、U/R/F/D/L/B 动作、整体旋转、规范坐标 |
| `tables.js` | 3,674,160 状态全表 BFS 距离、最短路径下降 |
| `provider.js` | 随机状态 -> 最短解 -> 取逆 -> 复算校验 |

## 坐标

2x2 没有固定中心，整体旋转等价。把 URF（角块 0）规范到 0 号槽位、朝向 0：

- 其余 7 个角块的排列：`7! = 5040`
- 其余 7 个角块的朝向：前 6 个自由，第 7 个由朝向和约束决定，`3^6 = 729`
- 总状态：`5040 * 729 = 3,674,160`

编码：

```
state = permIndex * 729 + oriIndex
```

## 动作

18 个 token（U/R/F/D/L/B × 1/2/3）在规范坐标下只有 9 个不同变换：

```
U = D, U2 = D2, U' = D'
R = L, R2 = L2, R' = L'
F = B, F2 = B2, F' = B'
```

BFS 只展开 9 个变换；生成打乱时在等价 token 里随机选择，保留六面记法。
这样距离仍然是最优物理步数。

## 生成流程

1. 均匀随机取 `0 .. 3,674,159`。
2. 距离 < 4 的状态重抽（WCA 4b3b）。
3. 按距离逐层下降，随机选一条最短路径。
4. 路径取逆，得到打乱。
5. 从复原态复算打乱，必须回到同一个规范状态。

## 实测

- 表构建：Node 约 2.9–4.6 s，Chromium 约 4.3–5.1 s（M1 优化后）。
- 最大距离：11。
- 打乱长度：平均约 9.0，常见 8–10。
- 单次生成：< 2 ms（表已缓存）。

## 限制

- 表在 worker 内缓存；首次请求有明显延迟。
- 输出是最优解取逆，通常比 TNoodle 的随机状态打乱短。
- 没有预计算表或压缩距离；M5 再优化。
