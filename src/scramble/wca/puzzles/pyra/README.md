# Pyraminx 本地求解器（M1）

## 文件

| 文件 | 内容 |
|---|---|
| `cubie.js` | 6 棱块 + 4 角尖模型、16 个动作、坐标与移动表 |
| `tables.js` | 1,866,240 索引空间 BFS、933,120 可达状态 |
| `provider.js` | 随机状态 -> 最短解 -> 取逆 -> 复算校验 |

## 模型

- `ep[6]`：槽位 -> 棱块编号
- `eo[6]`：棱块朝向，偶校验，32 种
- `co[4]`：角尖扭转，mod 3，81 种

索引空间 `720 * 32 * 81 = 1,866,240`，其中 `933,120` 个状态可达。
BFS 保留完整索引，生成时用 `distance >= 0` 过滤不可达状态。

动作与 csTimer 的 Pyraminx 模型一致：

- `U/L/R/B`：面转，循环 3 个棱块、翻转 2 个槽位、拧动 1 个角尖；
- `u/l/r/b`：角尖独立转动；
- 每个轴两个方向，共 16 个动作。

## 生成流程

1. 均匀随机取棱块排列、朝向、角尖扭转。
2. 过滤不可达状态和距离 < 6 的状态（WCA 4b3f）。
3. 按距离逐层下降，随机选一条最短路径。
4. 路径取逆，得到打乱。
5. 从复原态复算，必须回到同一个状态。

## 实测

- 表构建：Node 约 0.25–0.3 s，Chromium 约 0.3–0.9 s。
- 可达状态：933,120；最大距离：11。
- 打乱长度：平均约 7.4–7.8，常见 6–9。
- 单次生成：< 2 ms（表已缓存）。

## 限制

- 输出是最优解取逆，往往比比赛打乱短（会出现 6 步）。
- 没有随机 AUF 或非最优解策略；如果后续要更接近 TNoodle 的长度分布，
  需要额外设计。
