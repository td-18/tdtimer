# Skewb 本地求解器（M1）

## 文件

| 文件 | 内容 |
|---|---|
| `cubie.js` | 6 中心 + 4 可转动角 + 4 固定角模型、坐标与移动表 |
| `tables.js` | 9,447,840 索引空间 BFS、3,149,280 可达状态 |
| `provider.js` | 随机状态 -> 最短解 -> 取逆 -> 复算校验 |

## 模型

采用 csTimer 的 Skewb 坐标：

- `centers[6]`：中心块偶排列，`6! / 2 = 360`
- `corners[4]`：可转动角块偶排列，`4! / 2 = 12`
- `fixed[4]`：固定角块扭转，`3^4 = 81`
- `twist[4]`：可转动角块扭转，和约束 mod 3，`3^3 = 27`

索引空间 `360 * 12 * 81 * 27 = 9,447,840`；BFS 可达 `3,149,280`。
未达状态 `distance = -1`，生成时过滤。

动作是 4 个角轴 120° 转，每轴两个方向，共 8 个动作。

## 生成流程

1. 均匀随机取四组坐标。
2. 过滤不可达状态和距离 < 7 的状态（WCA 4b3c）。
3. 按距离逐层下降，随机选一条最短路径。
4. 路径取逆，得到打乱。
5. 从复原态复算，必须回到同一个状态。

## 实测

- 表构建：Node 约 1.9–2.4 s，Chromium 约 3.4–5.8 s。
- 可达状态：3,149,280；最大距离：11。
- 打乱长度：平均约 8.3–8.5，常见 7–10。
- 单次生成：< 5 ms（表已缓存）。

## 限制

- 索引空间比可达状态大 3 倍，随机采样要过滤；重试次数通常 < 30。
- 输出是最优解取逆，通常比 TNoodle 的随机状态打乱短。
- M5 可以考虑压缩距离表或预计算。
